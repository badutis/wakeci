# Configuration

One JSON file, `/etc/wakeci/config.json` on the controller host. Start from
[`controller/config.example.json`](https://github.com/badutis/wakeci/blob/main/controller/config.example.json),
or generate one with [`wakeci discover`](discover.md). Check it with
`wakeci check config.json`: it applies every rule the controller and the installer rely on,
and refuses unknown keys, so a typo such as `idle_minute` is reported instead of ignored.
`deploy.sh` and `install.sh` run it too.

Its first two keys are worth keeping:

- `"$schema"` points editors such as VS Code to
  [`config.schema.json`](config.schema.json), which gives completion and checks while you
  type;
- `"config_version": 1` is the format version. A future incompatible format raises it, and
  WakeCI refuses a version it does not know instead of misreading the file. Without it
  the file is read as version 1; `wakeci check`, the installer and the controller's log
  warn about it.

## Sources

A **source** is one place where runners are registered (`runners_path`: a repository's
runners, `repos/<owner>/<repo>`, or an organisation's, `orgs/<org>`), plus the
repositories whose queued jobs those runners take (`repos`), and the file holding its
read-only token (`token_file`).

A runner only counts for a job from the same source, and only if it has every label the
job asks for. This is the same rule GitHub uses to assign jobs.

## Machines

Every runner whose name starts with one of a machine's `runner_prefixes` belongs to that
machine. `rank`: lower ranks are woken first, so give faster machines a lower number.
`name` may hold letters, digits, `.`, `_` and `-`: it is also the machine label in
`/metrics`.

Every machine needs its own MAC and host, and no two machines may share a runner prefix.
A prefix should end where the number ends (`host1-`, not `host1`): otherwise `host1`
also matches the runners of `host10-`, which then belong to both machines, and
`wakeci check` warns about it. A value that still holds `FILL-IN` (what
`wakeci discover` writes) is refused.

The SSH key, `known_hosts` and every token file must be directly in `/etc/wakeci/`: the
installer changes their owners and modes as root, so it is never pointed at a file
elsewhere.

## Tokens

Use one fine-grained personal access token per source, with read access only:

- **repository source:** Actions: read, and Administration: read (needed to list
  repository runners);
- **organisation source:** Actions: read on the repositories, and Self-hosted runners:
  read on the organisation.

Check the exact permission names when you create the tokens: GitHub renames them from
time to time. A stolen token can read the queue and nothing else. `wakeci doctor` checks
that each token is valid, when it expires, and that it can read what it needs; it warns
about a classic token that can write.
